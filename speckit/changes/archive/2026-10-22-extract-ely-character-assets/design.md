# Design

## Context

`src/pet/rig.rs` 的 `PARTS` 保存 SVG 片段和图层属性，`part`、`eye`、`mouth`、`mark` 辅助函数补齐默认值。`Rig::new` 将片段包装为完整 SVG，并为每层生成缓存键；`paint` 使用 GPUI 的 SVG 遮罩绘制，以单独的颜色和透明度着色。`moved` 根据 `Bone` 和 `Pose` 决定可见性与矩阵。

`look.rs` 计算 Ely 专属姿态与动作时序，`gaze.rs` 叠加视线，`view.rs` 逐帧绘制并处理鼠标，`pet.rs` 和平台模块维持窗口与位置。这些行为不是本次重构目标。

已有测试通过 resvg/usvg 检查图层可解析且不越界，并检查跳跃时衣服与后发仍盖住边缘，以及关键部件和特效齐全。迁移时保留这些检查。

## Decisions

### 1. 使用内置资源目录，不定义公共角色包协议

采用 `assets/pet/ely/rig.json` 与 `assets/pet/ely/layers/<name>.svg`。JSON 保存有序图层数组，每层显式记录 name、asset、color、alpha、frame、pivot、binding；顶层保存原 `VIEW` 和头部转动中心。由辅助函数补齐的默认值在迁移时展开，避免把 Ely 的数值留在 Rust 中。

颜色用六位 RGB 字符串；绑定用带类型的对象，限定为现有 Bone 的类别及其 side、mouth 或 mark 参数。左右索引只允许 0 和 1。该格式是内置资源的内部表示，不承诺第三方兼容、版本迁移或任意骨骼能力。

`WIDTH`、`HEAD`、`ROOM` 等窗口尺寸及动画曲线参数保持当前实现，不在本次泛化。图层转动中心和头部共用转动中心属于资源；矩阵计算及姿态算法属于代码。

### 2. 每层保存完整 SVG，但保持原有遮罩语义

将现有 `svg(part)` 的输出迁移为完整 SVG 文件，保留 viewBox、width、height、描边、局部 defs 和 clipPath。颜色与整体透明度继续由描述和 GPUI `paint_svg` 提供，不能把单色遮罩误改为彩色图片绘制。

保留现有坐标、图层顺序及 `ely/<name>.svg` 缓存键语义。资源描述的 frame 与 SVG 根视口应一致，并通过测试检查。删除内联 SVG、`PARTS`、数据构造辅助函数及不再需要的 SVG 包装函数，不保留旧路径作为兼容回退。

### 3. 显式内嵌并在构造时解析，绘制阶段不做加载工作

用 `include_str!` / `include_bytes!` 内嵌 JSON 和 SVG。小型 Rust 资源索引只映射路径到字节，不重复颜色、坐标、顺序或绑定；无需新增依赖、修改发布脚本或在 build.rs 中增加资源生成器。

新增职责单一的资源模块，复用 serde/serde_json，反序列化为严格类型，校验后生成由 Rig 持有的图层数据；取代当前 `&'static Part` 引用布局。每次 rig 构造时解析一次，paint 只读取已准备的数据与字节，不访问磁盘、不解析 JSON、不重新拼装 SVG。

### 4. 错误必须指向资源，不能部分绘制

JSON 使用未知字段拒绝策略；校验名称唯一、资源存在、绑定合法、坐标有限、尺寸为正、RGB 合法及 alpha 范围。加载函数返回携带 `pet`、资源路径与字段/图层上下文的错误，不使用默认 rig 或跳过坏层。

在创建角色窗口前完成描述加载与校验；若失败，沿现有角色创建错误处理路径报告并不创建该角色窗口，不留下空透明窗口，也不擅自改变终端主体的生命周期策略。SVG 的结构与边界由现有 dev-only resvg/usvg 测试验证，运行时绘制错误继续明确记录。无需为此将 resvg 加入运行时依赖。

### 5. 迁移一致性优先于可扩展性

实施前从旧实现记录图层清单和代表性固定 Pose 的绘制计划：顺序、可见性、矩阵与透明度。覆盖所有动作绑定与表情分支，并包含状态切换、入场和点击叠加。迁移后与基线比较，不将旧素材表作为第二套生产实现保留。

保留图层边界、部件完整性和最高跳跃覆盖测试，并加入描述异常测试、SVG 视口与 frame 一致性测试和内嵌索引完整性测试。

在同一环境与固定姿态下进行前后图像比较，覆盖 calm、work、wait、fret、cheer、doze、wink；浮点/光栅差异如需容差，必须说明原因并检查差异图，不以宽松阈值掩盖素材变化。手动验证视线、点击、拖动、显示开关、边缘切换和不抢焦点。macOS 的 shot 仅在可用平台使用；其他平台使用可复现的测试夹具或本机截图，未测试的平台明确记录。

## Risks / Trade-offs

- 将 SVG 片段变为完整文件可能改变裁切或局部引用：保持旧包装结果，逐层用 usvg 检查，并做固定姿态对比。
- 元数据迁移可能漏掉辅助函数默认值：显式展开，并在删旧表前记录基线。
- 手工内嵌索引可能漏项：测试目录、描述引用和索引的一致性；本次接受小型索引维护成本，不引入通用目录打包系统。
- JSON 新增一次构造时解析成本：绘制热路径不解析，当前内置资源规模有限，暂不增加缓存或生成器。
- 用户不能通过替换安装目录文件更换角色：这是本次刻意边界，修改资源仍需重新构建。
- 角色数据依然使用 Ely 专属 Bone/Pose 语义：本次只拆分，不宣称已支持任意角色。
- 新资源文件与测试仍遵守手写文件不超过 500 行；必要时按职责拆文件，不靠压缩内容规避可读性。
